## 1. Contexto e motivação

### 1.1 Problema da V1 (estado atual deste repo)

A V1 aprende um transformador paramétrico único \(T_\theta\):

\[
T_\theta(x) = P_\theta\big(G_\theta\big(W_\theta(x)\big)\big)
\]

onde:
- \(W_\theta\): DCT **ou** DT-CWT com parâmetros **globais por banda** (escala/fase por nível×orientação, sem mapa espacial);
- \(G_\theta\): warp geométrico (flow de baixa resolução);
- \(P_\theta\): ajuste fotométrico local;
- opcionalmente máscaras faciais (elipse fixa / landmarks / band) limitam onde a transformação age.

**Limitações observadas / decisões históricas (`DECISIONS.md`):**
- Com o transformador V1 (DCT/wavelet **global** + flow/photo), máscaras parciais falharam em desidentificar — sinal de identidade fora da ROI sobrevivia.
- Trade-off cos×SSIM depende fortemente de flow/photo/amp — muitos hiperparâmetros.
- Early stopping por `score = ssim − cos` ajuda, mas o treino ainda é por **steps** com Adam apenas.
- DT-CWT na V1 é **global** (poucos parâmetros), diferente da meta-máscara **espacial** validada no projeto irmão.

**Hipótese revisada para V2:** com uma meta-máscara **espacial** (L2/L3) + SignSGD, **restringir a perturbação a ROIs** pode melhorar qualidade visual **sem** sacrificar tanto a desID quanto na V1. Por isso a V2 **mantém** `models/masks.py` e as flags atuais.

### 1.2 O que foi validado no projeto irmão (`dtcwt_mask_optimization`)

Pipeline Protego-adaptado com **meta-máscara universal no domínio DT-CWT** (consultar esse repo para código/paridade):

| Conceito | Onde no irmão |
|----------|----------------|
| Módulo | `protego_base/protego/dtcwt_mask.py` → `DTCWTMetaMaskModule` |
| Parâmetros | `delta_mag` / `delta_phase` **espaciais** por nível editável |
| Níveis default | J=3; editáveis **2 e 3**; nível **1 congelado** (JPEG) |
| Aplicação | \(W' = W + \Delta W_{\mathrm{meta}}\cdot e^{i\phi}\) → IDT-CWT → L∞ \(\varepsilon=16/255\) |
| Loss campeã (Phase 3.3) | média do cos no ensemble + SSIM hinge com peso adaptativo \(w\) |
| Otimizador campeão | **Protego / SignSGD**: `param -= lr * sign(grad)` |
| Dataset | `merged_lfw_celeba` com split fracionário CelebA |
| Ensemble treino | `fr_preset=small` (3 FRs) ou `full` (~9 FRs) |

**Resultado de referência (README do irmão):**
- Run: `20261015_055232_phase3_3_merged_p33_protego`
- Eval ~4058 imgs; **% cos < 0.5 ≈ 84.1%**; cos médio ≈ **0.327**; SSIM ≈ 0.935; LPIPS ≈ 0.118
- Adam no mesmo setup colapsa (cos≈0.999) — **SignSGD é essencial**.

### 1.3 Tese da V2 (neste repositório)

Integrar o **motor Phase 3.3** aqui, **substituindo** warp, foto e DCT no path V2, e **mantendo** o pipeline de máscaras ROI já implementado (elipse / band, flags idênticas).

A meta-máscara é **universal** (um \(\Delta W\) offline). A ROI **não é aprendida** — landmarks SCRFD ou elipse fixa definem onde a perturbação aparece. Entretanto, deve-se ter a opção assim como a validada no projeto irmão em que a região é aprendida ao longo do tempo.

**Duas ideias de composição** (implementar **nesta ordem**; distinção só por flag):

| | Ideia 1 — `--roi-compose pixel` (**default**, primeiro) | Ideia 2 — `--roi-compose wavelet` (depois) |
|--|--------------------------------------------------------|--------------------------------------------|
| O que faz | \(\Delta W\) full + **encaixe** pela ROI no pixel | \(\Delta W\) **só sob** a ROI nos coeficientes |
| Pipeline | DT-CWT(+ΔW) → IDT-CWT → **residual⊙M** → L∞ | \(M\to M_ℓ\) → DT-CWT(+ΔW⊙M_ℓ) → IDT-CWT → L∞ |
| O que se aprende | Params full-frame; loss viesada pela ROI | Update efetivo só onde \(M_ℓ>0\) |

> **Default:** Ideia 1. Ideia 2 só após Ideia 1 estável (smoke + treino curto verdes).

A V2 evolui este projeto de “transformador multi-módulo leve” para **produção da meta-máscara DT-CWT + ROI**, reusando CLI, early-stop e docs já existentes.

## 3. Mudanças conceituais e estruturais

### 3.1 Único módulo espectral: DT-CWT meta-máscara (+ ROI espacial)

**Substituir** o caminho espectral/geométrico/fotométrico do `LightweightDeIdentifier` (no treino V2) por um módulo equivalente a `DTCWTMetaMaskModule`, **composado** com a máscara ROI do Lightweight via `--roi-compose`.

#### Flag de composição

| Flag | Valores | Default | Quando implementar |
|------|---------|---------|--------------------|
| `--roi-compose` | `pixel` \| `wavelet` | **`pixel`** | `pixel` = Step 2 (Ideia 1); `wavelet` = Step 7 (Ideia 2) |

- `--no-face-mask` ⇒ \(M \equiv 1\): os dois modos colapsam para o path Phase 3.3 (perturbação full-frame).
- Checkpoint / `config.json` **obrigam** gravar `roi_compose`.
- Inferência/`apply` deve ler a flag do checkpoint (override CLI permitido e logado).

#### Ideia 1 — `--roi-compose pixel` (implementar primeiro)

Aprende \(\Delta W\) **em todo o campo**; **encaixa** a perturbação na ROI **depois** da reconstrução.

```
x → resolve_face_mask → M
  → DTCWTForward(J)
  → yh[ℓ] ← yh[ℓ] + ΔW_ℓ · e^{iφ}          # ΔW FULL (níveis editáveis)
  → DTCWTInverse → recon
  → residual = (recon − x) ⊙ M             # ENCAIXE ROI (recomendado)
  → residual = clamp(residual, −ε, ε)
  → x_prot = clamp(x + residual, 0, 1)
```

Variante blend (equivalente em espírito V1; escolher uma e fixar em `DECISIONS.md`):

```
x̃ = recon ⊙ M + x ⊙ (1 − M)
x_prot = apply_linf_budget(x̃, x, ε)
```

**Preferir residual⊙M** (L∞ só dentro da ROI).

#### Ideia 2 — `--roi-compose wavelet` (implementar depois; não quebra Ideia 1)

Restringe a aplicação de \(\Delta W\) **nos coeficientes** sob a ROI projetada por nível.

```
x → resolve_face_mask → M
  → para cada ℓ ∈ editable_levels:
        M_ℓ = downsample(M, size=H_ℓ×W_ℓ)   # bilinear / area; detach
  → DTCWTForward(J)
  → yh[ℓ] ← yh[ℓ] + (ΔW_ℓ ⊙ M_ℓ) · e^{iφ} # SÓ SOB ROI no wavelet
  → DTCWTInverse → recon
  → residual = clamp(recon − x, −ε, ε)     # opcional: ainda ⊙ M no pixel
  → x_prot = clamp(x + residual, 0, 1)
```

**Regra de não-regressão:** o branch `if roi_compose == "pixel": ... elif "wavelet": ...` deve deixar o path `pixel` **byte-a-byte equivalente** ao que passou nos testes da Ideia 1. Ideia 2 só adiciona código.

#### Sequência por batch (treino) — o que cos e SSIM medem

Nas **duas** ideias, a ordem do batch é:

```
1. X, paths
2. M = resolve_face_mask(...)          # ROI heurística (não treinável)
3. forward conforme --roi-compose      # pixel | wavelet  →  x_prot
4. cos  = mean_e cos(F_e(X), F_e(x_prot))     # SEMPRE sobre x_prot FINAL
5. ssim = SSIM(X, x_prot) c/ --ssim-region    # SEMPRE sobre x_prot FINAL
6. L = cos + w * hinge(min_ssim - ssim)
7. backward → update ΔW (Adam ou SignSGD)
```

| Sinal | Mede | Momento |
|-------|------|---------|
| **cos** | DesID: embeddings original vs protegida | **Depois** de ROI+L∞ (nunca sobre `recon` cru na Ideia 1) |
| **SSIM** | Qualidade perceptual no escopo `--ssim-region` | Idem, sobre \(x_{\mathrm{prot}}\) |
| ROI \(M\) | Onde a perturbação pode aparecer | **Antes** da loss (passo 2–3); não é termo da loss |

Diferença só no passo 3: Ideia 1 encaixa no pixel; Ideia 2 restringe no wavelet. A loss **não muda**.

#### Invariantes obrigatórios (ambos os modos)

1. Gradientes fluem de `x_prot` até `delta_mag` / `delta_phase` (\(M\) / \(M_ℓ\) com `detach`).
2. FRs congelados; filtros DT-CWT sem grad.
3. Default: nível 1 **fora** de `editable_levels`.
4. Sem warp / photo / DCT.
5. Fallback landmarks = elipse fixa (V1).

**Diferença crítica vs V1 DT-CWT:**
| | V1 Lightweight | V2 |
|--|----------------|-----|
| Params espectrais | `(1,6,J)` globais | `(1,C,6,H_ℓ,W_ℓ)` espaciais |
| Fórmula | `mag *= scale`, `phase += shift` | `W ← W + ΔW e^{iφ}` (⊙M_ℓ se wavelet) |
| ROI | ellipse/landmarks/band | **mesma API** + `--roi-compose` |
| Warp / photo | sim | **não** |
| L∞ | via amps | explícito `ε=16/255` |

### 3.2 Função de perda (Phase 3.3)

\[
\mathcal{L}
=
\frac{1}{|\mathcal{E}|}
\sum_{e\in\mathcal{E}}
\cos\big(F_e(X),\, F_e(X_{\mathrm{prot}})\big)
+
w \cdot \max(\texttt{min\_ssim} - \mathrm{SSIM}(X_{\mathrm{prot}}, X),\, 0)
\]

onde:
- \(\mathcal{E}\) = ensemble de treino (surrogates);
- \(\cos\) = similaridade cosseno média no batch após L2-normalize ( **minimizar** → menor = melhor desID );
- \(\mathrm{SSIM}\) respeita `--ssim-region` (paridade V1):
  - `full-landmarks` (default): SSIM na elipse `full` via landmarks — **independente** da ROI de transformação;
  - `mask`: SSIM só dentro da mesma \(M\) usada no blend;
  - implementação: preferir mapa SSIM + média ponderada pela máscara de escopo (como `ssim_index_masked` da V1) **ou** msssim full se `M≡1`;
- \(w\) = peso adaptativo Protego-style:
  - se SSIM ≥ `min_ssim * 1.01` e \(w > w_{\min}\): \(w \leftarrow w/2\)
  - se SSIM ≤ `min_ssim * 0.99` e \(w ≤ w_{\max}\): \(w \leftarrow 2w\)
  - se dentro da banda: \(w \leftarrow 1\)
  - defaults: \(w_{\min}=1/129\), \(w_{\max}=129\), \(w_0=1\)
- **Não** usar hinge `max(0, cos − target_cos)` da V1 no caminho V2 default.
- **Não** incluir TV, L2 pixel, flow_smooth, wavelet_l2 da V1 no default V2.

**Defaults sugeridos (alinhados ao campeão atual + ROI):**
| Flag | Default V2 |
|------|------------|
| `--min-ssim` / `--min_ssim` | `0.95` |
| `--epsilon` | `16/255` |
| `--lambda-id` | `1.0` (já embutido na média do cos) |
| `--image-size` | `224` |
| `--roi-compose` | `pixel` (Ideia 1; `wavelet` só após Step 7) |
| `--mask-mode` | `landmarks` |
| `--mask-shape` | `ellipse` |
| `--mask-regions` | `full` |
| `--ssim-region` | `full-landmarks` |

### 3.4 Níveis DT-CWT selecionáveis por flag

Antes do treino, o usuário escolhe quais níveis recebem parâmetros:


**Comportamento:**

- Se `1 ∈ editable_levels`: imprimir warning + registrar em `config.json`.
- Checkpoint deve salvar `editable_levels`, `J`, shapes de cada `delta_*`.
- Testes: smoke com `(2,)`, `(3,)`, `(2,3)` e assert de shapes + fluxo de grad só nos níveis listados.

### 3.5 Otimizador selecionável

| `--optimizer` | Update | LR default |
|---------------|--------|------------|
| `adam` | `Adam(params, lr)` | `1e-2` |
| `protego` | `param -= lr * sign(grad)` | `0.01 * epsilon` |

**Motivo (evidência no projeto irmão):** Adam → máscara inerte (cos≈1); SignSGD → cos≈0.28–0.35 no mesmo setup.

Implementar helper `_protego_sign_step` idêntico ao do irmão. Manter Adam para ablação / debug.

### 3.6 Loop de treino: épocas + early stopping revisado

**Hoje:**
- Este repo (V1): **steps** + early stop maduro (`score`/`cos`/`ssim`/`euclid`, patience, `transform_best.pt`).
- Projeto irmão: **epochs** + `max_train`, sem early stop.

**V2 desejado:** combinar o melhor dos dois (épocas + ES deste repo).

#### Proposta de loop

```
for epoch in 1..max_epochs:
  for batch in train_loader:
    forward → loss → backward → optimizer step
    log + tqdm postfix
    rolling checkpoint a cada ckpt_every steps
  # fim da época (ou a cada eval_every steps — ver flags)
  if early_stopping:
    metrics = validate(val_loader, train_frs)          # surrogates
    heldout = validate(val_loader, eval_frs)           # generalização
    score = early_stopping_score(...)
    save best if improved; stop if patience esgotada
```

#### Flags (síntese)

| Flag | Default sugerido | Notas |
|------|------------------|-------|
| `--epochs` / `--max-epochs` | `5` | teto (como Phase 3.3) |
| `--early-stopping` | **on** na V2 | opt-out `--no-early-stopping` |
| `--eval-every-epochs` | `1` | validar ao fim de cada época |
| `--eval-every-steps` | `0` (off) | opcional validação mid-epoch |
| `--patience` | `2` (em épocas) | recalibrar vs V1 (patience em evals de steps) |
| `--early-stopping-metric` | `cos` | **revisão:** na V2 preferir minimizar cos; `score=ssim-cos` como alternativa |
| `--min-delta` | `0.005` (cos) | evitar “melhoras” de ruído |
| `--val-max-samples` | `200` | durante treino; eval final pode ser maior |
| `--ckpt-every` | `1000` | `checkpoint_latest.pt` rolling |
| `--resume` | path | retoma na mesma pasta de run |

#### Revisão dos critérios de early stop (obrigatória na Step 5)

Documentar em `DECISIONS.md` após smoke:

1. **`cos` (min)** — alinhado à loss de identidade; recomendado default V2.
2. **`score = ssim − cos` (max)** — herança V1; útil se SSIM oscilar forte com SignSGD.
3. **`composite` (opcional v2.0.1):** parar só se cos melhorou **e** SSIM ≥ `min_ssim - δ` (ex. δ=0.03), para não “ganhar” desID destruindo qualidade.
4. Sempre salvar:
   - `meta_mask_best.pt` (melhor métrica de ES)
   - `meta_mask.pt` / `checkpoint_latest.pt` (último / rolling)
5. Held-out FR metrics **não** dirigem o early stop por default (só log) — evita overfit ao conjunto de eval FR; flag `--early-stop-on-heldout` fica **off**.

## 9. Critérios de aceitação globais da V2

A V2 está “pronta” quando:

1. **Treino default** (`--roi-compose pixel`) usa DT-CWT meta-máscara + ROI (sem warp/photo/DCT).
2. Flags `--mask-mode`, `--mask-shape`, `--mask-regions`, `--no-face-mask`, `--ssim-region` têm **a mesma semântica** da V1 deste repo.
3. `--roi-compose pixel` e `--roi-compose wavelet` coexistém; testes da Ideia 1 **não** regridem após o Step 7.
4. cos e SSIM são sempre calculados sobre \(x_{\mathrm{prot}}\) **final** (após composição ROI + L∞).
5. Loss = fórmula §3.2; logs mostram `cos_similarity` ↓ e `ssim` / `percep_weight`.
6. `--optimizer protego` e `adam` ambos funcionam; smoke compara comportamento.
7. `--editable-levels` altera quais tensores existem e recebem grad.
8. Ensembles `small` / `full` + held-out eval disjuntos.
9. Dataset merged com split fracionário reprodutível.
10. Early stopping documentado e ativo por default (ou decisão explícita em contrário).
11. Cada run é autocontido; logs incluem `image_size`, H×W, `roi_compose` e metadados de máscara.
12. Checkpoint/resume validados por teste.
13. Testes `test_v2_*` verdes (pixel + wavelet + ROI ellipse/band).
14. Docs (README + DECISIONS + este V2.md) coerentes.
15. Treino curto Protego+small+`full`+`pixel`: cos **claramente < 0.9** (tendência a < 0.5 no treino completo).
16. Com ROI ativa e `pixel`, residual fora de \(M\) ≈ 0; com `wavelet`, ΔW efetivo fora de \(M_ℓ\) ≈ 0.

## 10. Riscos e mitigações

| Risco | Mitigação |
|-------|-----------|
| VRAM com `full` ensemble | offload FR; default `small`; batch_size=2 |
| Portar FR_DB aumenta repo | git-lfs / download on first use (como Protego); não commitar pesos |
| Quebrar experimentos V1 | branch `feature/v2-...`; CLI legada intacta; máscaras compartilhadas |
| Early stop cedo demais com SignSGD | patience em épocas; min_delta; métrica `cos` + log SSIM |
| Nível 1 editável piora JPEG | warning + default sem 1; ablação documentada |
| ROI parcial volta a falhar na desID (lição V1) | default `full` landmarks; ablação documentada; `--no-face-mask` como baseline |
| Ideia 2 quebra Ideia 1 | branch `if/elif`; regressão obrigatória dos testes pixel no Step 7 |
| Downsample \(M_ℓ\) desalinhado | documentar interpolação; smoke visual overlay por nível |
| SCRFD falha em algumas imgs | fallback elipse fixa (já na V1); logar taxa de fallback |
| Divergência vs projeto irmão | smoke com `--no-face-mask`; mesmos seeds/split quando comparar |
| Artefatos fora do run | teste de isolamento Step 6; um único `out_dir` |
